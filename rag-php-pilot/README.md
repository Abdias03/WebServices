# RAG PHP pilot

This directory is an isolated PHP pilot. It does not replace or port the Java application in this repository.

## Requirements

- PHP 8.3 with PHPUnit's required extensions (including dom, mbstring, xml, xmlwriter).
- Composer 2 and PHPUnit 11.5, installed from the committed composer.lock.
- No Laravel, database, web server, external API or Docker is required for local unit tests.

Run from this directory:

```text
composer validate --strict
composer install --no-interaction --no-progress --prefer-dist --no-scripts --no-plugins
php vendor/bin/phpunit --configuration phpunit.xml --testdox
```

The committed dependency lockfile was generated by Composer. Install from it without updating dependencies. Do not ignore platform requirements to obtain a green result.

## Domain contract

Amounts are integer cents. Inputs are nonnegative integers whose operations fit PHP_INT_MAX. `subtotalCents(unitPriceCents, quantity)` returns their product. No rounding, tax, discounts, input-validation policy or overflow policy is included.

The baseline tests cover six independent cases: one unit, multiple units, zero quantity, zero price, cent precision and a larger supported order. They are ordinary PHPUnit tests and do not need RAG to run.

## Integration protocol

1. Publish the integration branch `rag/php-integration-20261029` only after local validation and a real composer.lock are available.
2. In RAG Test Studio, bind Abdias03/WebServices to that exact integration branch. Confirm the binding is ENABLED and the selected root is `rag-php-pilot` (the single Composer project).
3. Create the separate feature branch `rag/php-feature-handling-20261029` from the validated integration commit.
4. The feature adds a real pricing method with no existing test call. The original subtotal tests remain green. This deliberately leaves one eligible method for RAG to generate a test for; it is not a claim that the feature has been fully tested.
5. Only after the binding is confirmed, create a draft PR from feature to integration. Drafts do not trigger full RAG analysis.
6. Review the draft and obtain approval to mark it ready. Capture PR number, binding time, base/head SHA, AnalysisRun ID, ProjectVersion, Check and Sandbox execution ID.
7. Follow the Run. Inspect the proposed test, technical evidence and generated-method target. A green Check alone does not prove generation or execution.
8. Publish companion tests only after human review. Do not merge this pilot into master or change the default branch.

Keep test oracles and private experiment notes outside this public repository. Follow-up scenarios are documented in the local operator handoff, not shipped as target-test answers.

## Deliberate limits

No GitHub Actions workflow is added: RAG uses its GitHub App and PR webhooks. This pilot does not validate the Java code. It neither changes RAG backend configuration nor requests broader permissions. A baseline local PHPUnit run must not be confused with the RAG pipeline's currently incomplete automatic baseline feature.
